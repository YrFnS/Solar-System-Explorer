# Asset Sources and Redistribution Notes

Solar System Explorer combines locally stored source textures, generated derivatives, procedural Three.js visuals, and scientific orbital data. This file records which assets are generated by the project and where additional provenance checks are required before redistribution.

## Scientific orbital data

### Major planets

The approximate J2000 orbital elements for Mercury through Neptune are based on the low-precision planetary-position model published by NASA/JPL Solar System Dynamics:

- Source: <https://ssd.jpl.nasa.gov/planets/approx_pos.html>
- Intended range used by this project: approximately 3000 BC through 3000 AD
- Use: educational visualization only
- Not suitable for spacecraft navigation, occultation prediction, or observer-specific apparent coordinates

JPL Horizons remains the appropriate source for high-precision or observer-specific ephemerides:

- <https://ssd.jpl.nasa.gov/horizons/>

### Small bodies

Dwarf planets, comets, Centaurs, scattered-disc objects, and interstellar visitors use deterministic educational approximations derived from the local catalogue in `src/components/solar-system/data.ts`. These paths are not Horizons-grade ephemerides.

## Project-generated assets

The following files or file groups are generated by this repository and may be regenerated from source:

- `public/textures/earth-clouds.svg` — procedural SVG cloud mask created for this project
- `public/textures/optimized/*.webp` — build-time WebP derivatives generated from local source textures by `scripts/optimize-textures.mjs`
- procedural planet materials, atmospheres, rings, spacecraft, black holes, wormholes, asteroid fields, particle fields, orbit lines, and scientific overlays rendered by Three.js code

Generated WebP files are intentionally excluded from Git. Their redistribution status follows the license or terms of the original source texture from which each derivative was generated.

## Local texture inputs

Files under `public/textures/` are treated as source inputs. The project license does **not** automatically grant rights to third-party texture artwork.

Before publishing a commercial redistribution or an asset pack:

1. Verify the origin and license of every non-generated source texture.
2. Preserve any attribution required by the original author.
3. Replace any texture whose origin cannot be established with a self-created, NASA public-domain, or otherwise clearly licensed alternative.
4. Do not assume that an image being publicly downloadable makes it public domain.

The ring renderer supports the radial-strip convention commonly used by Solar System texture collections. That compatibility statement is not a license grant for any particular texture file.

## Procedural model fallbacks

The repository previously contained five `.glb` paths that were Git LFS pointer text rather than binary glTF files:

- ISS
- Hubble Space Telescope
- Voyager
- James Webb Space Telescope
- ʻOumuamua

Those invalid pointer files were removed. The application uses lightweight procedural Three.js renderers for these objects, avoiding broken downloads and unclear binary-asset provenance.

## Runtime-generated screenshots

Screenshots are created locally in the visitor's browser from the WebGL canvas. They are stored as temporary WebP object URLs for the current session only, capped at 12 images, and are not uploaded by the application.

## Adding a new asset

For every new texture, model, sound, or data file, add an entry containing:

- file path
- creator or source organization
- original source URL
- license or terms
- required attribution
- whether the file was modified
- whether generated derivatives are committed or produced at build time

Assets without a known redistribution basis should not be merged into a release branch.
