# Asset Sources and Redistribution Notes

Solar System Explorer combines locally stored source textures, generated derivatives, procedural Three.js visuals, and scientific orbital data. This file records generated assets and where provenance checks remain required before redistribution.

## Scientific orbital data

### Major planets

Approximate J2000 orbital elements for Mercury through Neptune are based on the low-precision planetary-position model published by NASA/JPL Solar System Dynamics:

- Source: <https://ssd.jpl.nasa.gov/planets/approx_pos.html>
- Intended range used by this project: approximately 3000 BC through 3000 AD
- Use: educational visualization only
- Not suitable for spacecraft navigation, occultation prediction, or observer-specific apparent coordinates

JPL Horizons remains the appropriate source for high-precision or observer-specific ephemerides:

- <https://ssd.jpl.nasa.gov/horizons/>

### Small bodies

Dwarf planets, comets, Centaurs, scattered-disc objects, and interstellar visitors use deterministic educational approximations derived from the local catalogue in `src/components/solar-system/data.ts`. These paths are not Horizons-grade ephemerides.

## Project-generated assets

The following files or groups are generated by this repository:

- `public/textures/earth-clouds.svg` — procedural SVG cloud mask created for this project.
- `public/textures/optimized/*.webp` — build-time WebP derivatives generated by `scripts/optimize-textures.mjs`.
- `public/textures/ktx2/<tier>/*.ktx2` — committed GPU-compressed derivatives generated by `scripts/encode-ktx2.mjs`.
- `public/basis/basis_transcoder.js` and `public/basis/basis_transcoder.wasm` — generated build outputs copied from the installed Three.js package by `scripts/sync-basis-transcoder.mjs`.
- Procedural planet materials, atmospheres, rings, spacecraft, black holes, wormholes, asteroid fields, particle fields, orbit lines, and scientific overlays rendered by project code.

Generated WebP and KTX2 files remain derivative works of their source textures. Redistribution follows the license or terms of each original source—not merely the repository's code license.

## KTX2/Basis catalogue

The active manifest contains 13 unique texture IDs and three quality tiers, producing 39 committed KTX2 files:

- `sun`
- `mercury`
- `venus`
- `earth`
- `moon`
- `mars`
- `jupiter`
- `saturn`
- `uranus`
- `neptune`
- `pluto`
- `earth-clouds`
- `saturn-ring`

The ring map is shared by Saturn and Uranus. The Moon map also supplies compatible local aliases and near-Earth rocky objects. The Earth and cloud entries replace historical remote aliases with owned local sources.

Colour maps use BasisLZ/ETC1S. The alpha-sensitive cloud and ring maps use UASTC with Zstandard supercompression. Mipmaps are generated by pinned Khronos KTX Software 4.4.2, and each output is validated with `ktx validate --gltf-basisu`.

The committed `.ktx2` files are ordinary binary Git payloads rather than Git LFS pointers, ensuring static deployments receive actual texture data. Basis JavaScript/WASM files are generated from the exact installed Three.js version and are not committed.

KTX2 is an upgrade path, not a single point of failure. A quality-tiered WebP remains available whenever a KTX2 asset, browser format, WebAssembly runtime, network request, or transcode operation fails.

## Active source inputs

The full runtime catalogue is derived from local files under `public/textures/`. Inactive or unused image files are not encoded merely because they exist in that directory.

Before publishing a commercial redistribution or asset pack:

1. Verify the creator, source, and license of every non-generated source texture.
2. Preserve all attribution required by the original author or organization.
3. Replace any texture whose origin cannot be established with a self-created, NASA public-domain, or otherwise clearly licensed alternative.
4. Do not assume public download availability means public-domain status.
5. Apply the same provenance rules to WebP and KTX2 derivatives.

The ring renderer's support for common radial-strip conventions is a technical compatibility statement, not a license grant for any particular image.

## Procedural model fallbacks

The repository previously contained five `.glb` paths that were Git LFS pointer text rather than binary glTF files:

- ISS
- Hubble Space Telescope
- Voyager
- James Webb Space Telescope
- ʻOumuamua

Those invalid pointer files were removed. The application uses lightweight procedural Three.js renderers for these objects, avoiding broken downloads and unclear binary-asset provenance.

## Runtime-generated screenshots

Screenshots are created locally from the WebGL canvas. They are stored as temporary WebP object URLs for the current session only, capped at 12 images, and are not uploaded by the application.

## Adding a new asset

For every new texture, model, sound, or data file, record:

- repository path
- creator or source organization
- original source URL
- license or terms
- required attribution
- whether the asset was modified
- generated derivative paths
- whether derivatives are committed or produced at build time
- whether the asset is active in the KTX2 manifest

Assets without a known redistribution basis should not enter a release branch.
